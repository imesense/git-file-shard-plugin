# Модель ветвления Git

<!-- markdownlint-enable MD025 -->

[English](./git-branching-model.md) | Русский

В документе описаны принципы сопровождения репозитория проекта и стратегии управления ветками.

## Стиль ведения истории изменений

Проект придерживается линейности изменений, чтобы:

- Упростить проверку кода и разделение на компоненты.
- Сохранить четкую хронологическую последовательность.
- Уменьшить количество конфликтов слияния.
- Упростить понимание изменений.

## Типы веток

### Постоянные ветки

- `default`:
  - Главная ветка для активной разботки.
  - Хранит в себе стабильное состоние проекта.
  - Защищённая ветвь (прямой доступ к ветке получают только сопровождающие).
  - Изменения вносятся с помощью запросов на слияние.
  - Прямые коммиты запрещены.

### Рабочие ветки

- `feature`:
  - Каждая новая функция разрабатывается в отдельной ветке, что помогает изолировать изменения.
- `fix`:
  - Используются для исправлений непосредоственно в резизной версии проетка.

### Формат

Для имён рабочих веток используется следующий формат именования:

```text
feature/<short-descriptive-name>
fix/<short-descriptive-name>
```

Например: `feature/user-authentication`

## Правила управления ветками

### 1. Создание

- Ветвитесь от `default`, изменения сливаются обратно после завершения работы.
- Оставляйте ветку короткоживущей: стремится минимизировать время жизни веток, часто и регулярно сливая измения в `default`.
- Ограничьте область действия ветки одним логически завершенным изменением: не смешивайте рефакторинг с добавлением новой функциональности или решенем проблем

### 2. Именование

- Используйте строчные буквы.
- Разделяйте слова дефисами.
- Соблюдайте длину имён веткок в 30 символов.
- Не используйте специальные символы.

### 3. Синхронизация изменений

- Регулярно выполняйте перебазирование на `default`.
- Разрешайте конфликты в рабочей ветке.

### 4. Чистка

- Удаляйте влитые ветки.
- Архивируйте экспериментальные ветки, если они сохранились.
- Регулярно удаляйте устаревшие ветки.

## Регламент слияния изменений

Изменения выполняются в соответствии с этим рабочим процессом:

1. Создание ветки от `default`.
2. Работа над текущей задачей и фиксация изменений.
3. Создание запроса на слияние или извлечение.
4. Проведение код ревью и CI/CD проверок.
5. Выполнение перебазирования на последний `default`.
6. Схлопывание коммитов при необходимости.
7. Получение подтверждения сопровождающего на слияние .
8. Объединение через стратегию перемотки.
